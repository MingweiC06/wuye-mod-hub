# 乌叶MC 粉丝站：个人信息出境合规调研

> **一句话结论**：据《促进和规范数据跨境流动规定》第五条第一款第（四）项（下称 §5(1)(4)），在出境数据不含敏感个人信息、且自当年 1 月 1 日起累计去重人数不足 10 万人的前提下，本站可免予申报安全评估、订立标准合同和通过认证，当前无需标准合同备案；若确有不满 14 周岁用户信息（属敏感个人信息），该豁免不适用，应按第八条订立标准合同或通过认证，并履行监护人同意等义务。
>
> 调研基准日：2026-11-18。本文仅依据公开法规、部门规章和官方问答，不构成法律意见或合规保证。

## 一、事实与适用档位

- 处理者：中国境内个人运营者；页面目前仅用昵称「乌叶MC」+ 抖音私信联系，真实姓名/主体待确认。
- 出境事实：OCI **us-ashburn-1** 已存储投票去重摘要、许愿昵称与内容、评论、下载解锁抖音昵称、认领昵称与一次性钥匙、赞助金额/备注/留言、审计日志（截断 IP 摘要 sha256 前 16 位），构成个人信息出境。
- 备份计划：Backblaze B2 **EU Central**，客户端 AES-256-GCM 加密后上传，服务商仅见密文；数据仍存储于境外。
- 规模：抖音频道约 1.8 万粉丝，但实际提交数据的去重人数远低于 1 万；许愿约 20 条、投票约 700、评论数十条、下载验证昵称数十条、赞助记录个位数、审计日志数百行。
- 不收集：手机号、身份证号、邮箱、原始 IP、User-Agent、支付流水、位置、通讯录；无账号体系、不接入抖音登录；未被告知或公布为重要数据（《规定》第二条）。
- 未成年人：站点面向普通玩家，不专门面向儿童，但无法做年龄验证，可能存在 <14 岁用户填写昵称。
- 现有技术措施：TLS 1.3、scrypt 存管理码哈希、限流、审计日志、Cookie HttpOnly+SameSite=Lax+Secure、无第三方 CDN/统计。

| 情形 | 适用档位 | 应做程序 |
|---|---|---|
| 无敏感个人信息，年累计去重 <10 万人 | §5(1)(4) | 免评估、免标准合同、免认证 |
| 有 <14 岁信息等敏感个人信息，年累计敏感 <1 万人 | 《规定》§8 | 标准合同 **或** 认证 |
| 非敏感 10 万–100 万人 | 《规定》§8 | 标准合同 **或** 认证 |
| 非敏感 ≥100 万人，或敏感 ≥1 万人 | 《规定》§7(2) | 安全评估 |

## 二、关键条款表

| 条款 | 要点（原文短句） | 对本站的适用 |
|---|---|---|
| 《规定》§2 | “未被相关部门、地区告知或者公开发布为重要数据的，不需要作为重要数据申报” | 无需重要数据评估；仍应自我识别 |
| 《规定》§5(1)(4) | “自当年1月1日起累计向境外提供不满10万人个人信息（不含敏感个人信息）” | 非敏感档可免三项程序；人数按自然人去重（答记者问 Q11） |
| 《规定》§7(2) | “100万人以上个人信息（不含敏感个人信息）或者1万人以上敏感个人信息” → 安全评估 | 本站远未达到；应设台账监控 |
| 《规定》§8 | “10万人以上、不满100万人……或者不满1万人敏感个人信息” → 标准合同或认证 | 一旦有 <14 岁数据即落入 |
| 《规定》§10 | “履行告知、取得个人单独同意、进行个人信息保护影响评估等义务” | 豁免程序不等于豁免义务 |
| 《规定》§11 | 数据安全保护义务；事件“及时向省级以上网信部门和其他有关主管部门报告” | 需书面应急预案与报告路径 |
| 《规定》§13 | 与旧办法“不一致的，适用本规定” | 旧“10 万以下可订标准合同”改为“10 万以下免予程序” |
| PIPL §28 | 敏感个人信息包括“不满十四周岁未成年人的个人信息” | <14 岁昵称亦属敏感 |
| PIPL §31 | 处理 <14 岁信息应取得“父母或者其他监护人的同意”；制定“专门的个人信息处理规则” | 若处理，须监护人同意 + 专门规则 |
| PIPL §38 | 出境应具备评估、认证、标准合同等条件之一；“保障境外接收方……达到本法规定的个人信息保护标准” | 豁免源于《规定》§5(1)(4)；仍须保障接收方合规 |
| PIPL §39 | 告知接收方名称/联系方式/目的/方式/种类/权利行使；“取得个人的单独同意” | 必须单独同意，不能混入一般隐私政策 |
| PIPL §51 | 分类管理、加密/去标识化、权限、培训、应急预案 | 现有 TLS/scrypt/限流/审计可部分对应，书面制度待核 |
| PIPL §55 | 处理敏感个人信息、向境外提供个人信息 → 事前 PIPIA | 出境与 <14 岁数据均触发 |
| PIPL §56 | PIPIA 三项内容；报告和记录“至少保存三年” | 留档 ≥3 年 |
| PIPL §72 | “自然人因个人或者家庭事务处理个人信息的，不适用本法” | 公开运营的粉丝站难以主张；待确认 |
| PIPL §73(1) | 处理者包括“组织、个人” | 个人可成为处理者；备案实操待确认 |
| 《标准合同办法》§4 | 旧门槛：处理 <100 万人、上年累计非敏感 <10 万人、敏感 <1 万人 | 已被《规定》§8 取代，作对比 |
| 《标准合同办法》§5 | PIPIA 重点（目的必要性、规模敏感性、接收方能力、泄露风险、外国法律影响等） | 可直接作为 PIPIA 提纲 |
| 《标准合同办法》§7 | 生效后 10 个工作日内向省级网信部门备案；材料含标准合同 + PIPIA 报告 | 若走合同路线，注意 10 日时限 |

## 三、新旧门槛差异

| 维度 | 2023《标准合同办法》 | 2024《规定》 |
|---|---|---|
| 计数起点 | 自上年 1 月 1 日起 | 自当年 1 月 1 日起 |
| 非敏感 | 上年累计 <10 万人可订标准合同，且处理 <100 万人 | <10 万人全免；10 万–100 万人合同/认证；≥100 万人评估 |
| 敏感 | 上年累计 <1 万人可订标准合同，且同时满足其他三项条件 | 本站场景无免予档；<1 万人合同/认证；≥1 万人评估 |
| 处理总量前提 | 处理个人信息 <100 万人 | §8 按年度出境数量分档，未再重复该前提 |
| 评估有效期 | 2 年 | 3 年（§9） |
| 备案时限 | 生效后 10 个工作日内 | 未变（§7 仍适用） |
| 衔接 | — | 旧规与《规定》不一致的，适用《规定》（§13） |

## 四、即使豁免也必须做

- **告知（PIPL §17、§39；敏感另加 §30）**：告知处理者姓名/名称与联系方式、境外接收方（Oracle/Backblaze 具体签约实体）名称与联系方式、目的（网站托管、加密备份）、方式（存储/备份）、信息种类、境外保存地点与期限、个人权利行使方式（含向接收方行使）、敏感信息的必要性与影响；目前仅用昵称，是否满足“姓名”要求待确认。
- **单独同意（§39；敏感 §29；<14 §31）**：在提交投票、许愿、评论、下载解锁、认领、赞助前，以独立勾选/弹窗取得跨境单独同意，不得默认勾选、不得与一般隐私政策捆绑；<14 岁由监护人同意（跨境单独同意与监护人同意的衔接待确认）；提供撤回渠道并记录同意版本。
- **PIPIA（§55、§56；《规定》§10）**：出境前完成并留存，至少覆盖：目的正当必要与最小化；数据规模/种类/敏感度；接收方合同、加密、访问控制、子处理者与再提供；境外保存与删除；美国/欧盟法律环境与政府调取风险；个人权利救济渠道；现有措施与剩余风险。报告和处理记录保存 ≥3 年。
- **接收方尽调与合同/措施（§38 第三款、§21）**：核验 Oracle、Backblaze 的签约实体、DPA/子处理者清单、数据所在地、删除与返还机制、安全事件通知、配合权利请求的义务；免费/自助套餐是否提供可签署的数据处理条款，待确认。新增 B2 属于接收方/保存地点变化，若走合同路线应按《标准合同办法》§8 重新评估并补充或重订备案。
- **安全措施（§51）**：在 TLS 1.3、scrypt、限流、审计日志、Cookie 安全属性、无第三方 CDN/统计之外，补齐书面内部制度、数据分类、最小权限与培训、应急预案；定期检查备份密钥与恢复流程。
- **记录与台账（§56；《规定》§10、§11）**：建立出境台账（按自然人去重的人数、信息种类、接收方、时间、目的），监控 1 万/10 万/100 万阈值；保存同意记录、PIPIA、合同/备案材料、接收方尽调与事件记录。
- **权利响应与事件报告（§44–§50、§57；《规定》§11）**：提供查阅、复制、更正、删除、撤回同意的渠道；明确用户向境外接收方行使权利的方式；发生泄露、篡改、丢失时立即补救并按规定通知部门和用户。

## 五之二、本轮已落地的工程措施（2026-11-19）

- **单独同意**：许愿、解锁下载、认领昵称、赞助四个表单各有一个独立勾选框，默认不勾选；前端校验 + 服务端再校验，缺少时返回 `400 consent_required`，不会保存任何内容。公开页面（浏览、看视频、投票、点赞）不受影响。
- **同意证据**：通过后写入 `consent_records`（`policy_version`、`scope=cross-border`、`purpose`、`created_at`、`age_confirmed`、`target_type`/`target_id`），不复制昵称、金额、留言等个人信息内容；删除对应记录时一并删除同意证据（`lib/consent.js`）。
- **年龄确认**：同一批表单另有一个「我确认已年满 14 周岁」勾选框，未勾选返回 `400 age_required`。不收集出生日期；勾选只是自述，**不等于取得监护人同意**，页面已如实说明。已知 <14 岁数据可按类别在后台停止处理并删除。
- **假名化定性修正**：`voter_key` 是设备标识的 HMAC、`ip_hash` 是截断 SHA-256。二者属**假名化个人信息，不是匿名数据**——服务器仍能关联同一设备的行为。页面已改为「假名化不等于匿名」，投票/点赞不再宣称「不含身份信息」。
- **数据删除**：后台「数据删除」支持 fans（下载昵称）、supporters（榜单昵称）、profiles（昵称档案）、sponsorships（赞助记录）四类，事务内处理关联数据，审计不含个人信息；每次删除需管理员会话 + 重输管理码 + 确认短语。
- **尚未完成**：PIPIA 报告与出境台账、Oracle/Backblaze 接收方尽调与合同、<14 监护人同意流程、认证或标准合同备案（是否需要见第一节结论）。
- **待确认风险**：投票、点赞不收集昵称，但会出境设备 HMAC 摘要。若按 PIPL §39 认定这也构成「向境外提供个人信息」，则同样需要单独同意；本轮未加勾选，等专业意见后再决定。

## 六、待专业人士确认（10 项）

1. 运营者主体：自然人、个体工商户还是企业；真实姓名/注册信息；能否主张 PIPL §72“个人或者家庭事务”豁免（公开运营通常难以适用）。
2. 自然人能否以个人身份完成标准合同备案；无统一社会信用代码如何填报；是否需先注册个体工商户/企业。国家层面规定未排除自然人，但地方备案指引（如福建 2023 版）按单位主体要求统一社会信用代码证件、法定代表人身份证件，实操待向省级网信部门确认。
3. Oracle/Backblaze 的境外签约实体、是否接受中国标准合同范本或认证安排；免费/自助套餐是否提供 DPA。
4. B2 客户端加密、服务商仅见密文，是否影响“出境”定性或门槛；官方公开规则未见明确，在确认前宜按出境场景纳入告知、同意与 PIPIA。
5. <14 岁用户的识别方式与监护人同意的可操作机制；无法识别时是否应禁止 <14 岁填写或删除其数据；在完成合同/认证前宜避免继续出境该等敏感数据。
6. 用户自由文本中自述健康、宗教、特定身份等敏感信息的识别与处理规则。
7. 个人信息保护认证对自然人的可行性、成本与周期。
8. Oracle（美国）与 Backblaze（美国公司，数据存于欧盟）所在国法律环境（执法调取、数据本地化）对 PIPIA 与合同履行的影响。
9. 赞助金额/备注是否构成金融账户信息（若含账号、流水或支付凭证）。
10. 现有隐私政策/用户协议是否已包含出境告知与单独同意；若未包含，补齐方式与生效时间。
